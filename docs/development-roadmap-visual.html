ClaimLens Development Roadmap

데이터 기반에서 멀티에이전트까지

ClaimLens는 먼저 KIPRIS 청구항 데이터를 PostgreSQL에 안정적으로 저장하고, 그 위에 Pinecone 검색, V1 순차 Agent workflow, V2 Supervisor Multi-Agent, V3 Reflection Loop를 단계적으로 쌓는다.

첫 번째 목표

KIPRIS → PostgreSQL 저장 성공

멀티에이전트보다 먼저 중요한 것은 Agent가 사용할 실제 데이터 기반이다. `patentClaimInfo` 응답을 `claims` 테이블에 안정적으로 저장하는 것이 첫 완료 기준이다.

1. `patents`, `claims` 테이블 생성
2. `patentClaimInfo` 호출
3. `raw_text`, `normalized_text` 저장
4. 삭제항과 독립항 판별

최종 목표

Multi-Agent Patent Analysis System

단순 검색 서비스가 아니라 Supervisor가 Search, Claim, Parsing, Matching, Validation, Report Agent를 조정하고, Validation 결과에 따라 재계획과 fallback을 수행하는 시스템으로 발전시킨다.

Supervisor Agent: 전체 상태와 재시도 관리
Specialist Agents: 검색, 청구항, 파싱, 매칭, 검증, 보고서
Reflection Loop: 근거 부족 시 재검색/재매칭
Bounded Autonomy: 무한 호출/무한 재시도 방지

Phase별 상세 계획

Phase 목표 주요 작업 완료 기준
0. Foundation 백엔드와 DB 연결 기반 FastAPI 설정, env 정리, SQLAlchemy/Alembic 준비 DB connection test 통과
1. PG Schema 저장 구조 확정 patents, claims, claim_elements, migration 작성 테이블 생성 및 insert/select 가능
2. Collector KIPRIS 데이터 수집 검색 API, patentClaimInfo, 정규화, upsert 10건 seed 저장 성공
3. Claim Parsing 청구항 구성요소 분해 독립항 판별, rule split, parser confidence 저장 독립항 1개가 3-12개 element로 분해
4. Pinecone 의미 검색 구축 embedding 생성, vector upsert, PG 원문 조회 연결 제품 설명으로 관련 청구항 top-k 검색
5. V1 Workflow claim chart 생성 Input, Search, Parser, Matcher, Validator, Report 연결 제품 설명 입력 시 claim chart 출력
6. V2 Supervisor 멀티에이전트 확장 Supervisor, Specialist Agent contracts, decision logs Supervisor가 재실행/fallback 결정
7. V3 Reflection 자기검증/복구 루프 evidence_missing, query rewrite, bounded retry 근거 부족 시 재검색 또는 uncertain downgrade
8. Frontend UI 포트폴리오 데모 SSE timeline, 후보 특허, claim chart, report UI 분석 진행 상황이 실시간 표시
9. Packaging 면접/포트폴리오 정리 테스트, README, screenshots, demo scenario 로컬 재현 가능한 데모 완성

구현 순서 요약

PG schema, collector, claims 저장, 정규화까지 먼저 끝낸다.

Search Next
